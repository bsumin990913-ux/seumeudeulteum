# 데이터베이스 실행 순서

Supabase 대시보드 → SQL Editor 에 **위에서부터 차례로** 붙여넣고 Run 하면 됩니다.
전부 여러 번 돌려도 안전하게 만들어져 있습니다(있는 건 건드리지 않고 없는 것만 채웁니다).

| 순서 | 파일 | 무엇이 생기나 |
|---|---|---|
| 1 | `setup.sql` | 후보(candidates) · 매칭(matches) · 담당자(managers) |
| 2 | `upgrade_v3.sql` | 관리자 메모, 매칭 타임라인, 사진 저장소(photos) |
| 3 | `upgrade_v4.sql` | 거절 기록(rejections), 블랙리스트, 스레드 홍보 |
| 4 | `upgrade_v5.sql` | 공개 신청 폼(applications), 신청 사진 저장소(apply) |
| 5 | `upgrade_v6.sql` | 연락처를 스레드 계정으로 |
| 6 | `upgrade_v7.sql` | 후기(reviews), 숫자 스트립(site_stats), 후기 저장소 |
| 7 | `upgrade_v8.sql` | '오늘의 검사' 결과 받아두기 |

## 주의

`upgrade_v4.sql` 과 `upgrade_v5.sql` 은 **원본 파일이 분실되어 다시 만든 것**입니다.
관리자 도구와 신청 폼이 실제로 읽고 쓰는 값을 기준으로 복원했기 때문에 동작에는 문제가 없지만,
이미 운영 중인 데이터베이스와 컬럼 기본값이 미세하게 다를 수 있습니다.
운영 중인 프로젝트에 돌리기 전에 **Supabase → Database → Backups** 에서 백업을 한 번 받아두세요.

## 저장소(Storage) 버킷 3개

| 버킷 | 읽기 | 쓰기 | 쓰임 |
|---|---|---|---|
| `photos` | 공개 | 주선자만 | 후보 사진 |
| `apply` | 공개 | **누구나** (신청 폼) | 신청서 사진 |
| `reviews` | 공개 | 주선자만 | 후기 캡처 |

세 버킷 모두 **읽기가 공개**입니다. 주소를 아는 사람은 로그인 없이 사진을 볼 수 있어요.
주소가 새어 나가지만 않으면 문제가 없지만, 개인정보처리방침의 "다른 사람의 신청서를
조회할 수 없습니다"는 데이터베이스에만 해당한다는 점을 알고 계셔야 합니다.
더 조이려면 버킷을 비공개로 바꾸고 `createSignedUrl()` 로 바꿔야 하는데,
그러면 관리자 도구의 사진 표시 코드도 함께 손봐야 합니다.
